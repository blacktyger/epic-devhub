## Which surface to target

| Task | Surface | Credential |
| --- | --- | --- |
| Node status, peers | Node `/v2/owner` | Basic, secret auto-created |
| Blocks, headers, kernels, mempool | Node `/v2/foreign` | None |
| Submit a raw transaction | Node `/v2/foreign` | None |
| Anything involving keys or balances | Wallet Owner API `/v3/owner` | ECDH handshake and a wallet token |
| Receive a transfer | Wallet Foreign API, or `epic-wallet listen` | None, by design |

The node's JSON-RPC methods are split across two paths and the split is not intuitive: `/v2/owner` is
administration only, and every chain read is on `/v2/foreign`. See
[the node API](/api/node#which-json-rpc-method-lives-where).

The node surface is straightforward JSON-RPC. The wallet Owner API adds an encrypted envelope; see
[connect and read](/examples/wallet-connect).

## Conventions in these examples

- The node is at `http://127.0.0.1:3413` and the wallet Owner API at `http://127.0.0.1:3420`.
- Amounts are integer **freemen**. 1 EPIC is `100000000`.
- Secrets are read from their files rather than pasted inline. Never hard-code a wallet password or an
  API secret in code you keep.
- Errors are checked, because Epic's JSON-RPC wraps application results in an `Ok`/`Err` envelope
  *inside* a successful HTTP 200. Ignoring that is the most common integration bug.

## The response envelope

Every Epic JSON-RPC method returns HTTP 200 with a JSON-RPC `result`, and inside that result is a second
envelope:

```json
{
  "id": 1,
  "jsonrpc": "2.0",
  "result": {
    "Ok": { "...": "the actual data" }
  }
}
```

A failed operation returns `Err` in the same position:

```json
{
  "id": 1,
  "jsonrpc": "2.0",
  "result": {
    "Err": { "NotEnoughFunds": { "available": 0, "needed": 100000000 } }
  }
}
```

So a request can succeed at the HTTP layer, succeed at the JSON-RPC layer, and still have failed. Write
one unwrap helper and use it everywhere:

<Tabs groupId="lang">
<TabItem value="py" label="Python">

```python title="epic_client.py"
def unwrap(response: dict):
    """Unwrap Epic's nested Ok/Err result envelope."""
    if "error" in response:
        raise RuntimeError(f"JSON-RPC error: {response['error']}")

    result = response.get("result", response)
    if isinstance(result, dict):
        if "Err" in result:
            raise RuntimeError(f"Epic returned an error: {result['Err']}")
        if "Ok" in result:
            return result["Ok"]
    return result
```

</TabItem>
<TabItem value="js" label="JavaScript">

```js title="epicClient.js"
export function unwrap(response) {
  if (response.error) {
    throw new Error(`JSON-RPC error: ${JSON.stringify(response.error)}`);
  }
  const result = response.result ?? response;
  if (result && typeof result === 'object') {
    if ('Err' in result) {
      throw new Error(`Epic returned an error: ${JSON.stringify(result.Err)}`);
    }
    if ('Ok' in result) return result.Ok;
  }
  return result;
}
```

</TabItem>
<TabItem value="rust" label="Rust">

```rust title="src/client.rs"
use serde_json::Value;

/// Unwrap Epic's nested Ok/Err result envelope.
pub fn unwrap(response: Value) -> anyhow::Result<Value> {
    if let Some(err) = response.get("error") {
        anyhow::bail!("JSON-RPC error: {err}");
    }
    let result = response.get("result").cloned().unwrap_or(response);
    if let Some(err) = result.get("Err") {
        anyhow::bail!("Epic returned an error: {err}");
    }
    Ok(result.get("Ok").cloned().unwrap_or(result))
}
```

</TabItem>
<TabItem value="sh" label="Shell">

```bash
# jq exits non-zero when the Err branch is present, so a pipeline fails loudly.
epic_ok() {
  jq -e 'if .error then error("jsonrpc: \(.error)")
         elif .result.Err then error("epic: \(.result.Err)")
         else (.result.Ok // .result) end'
}

curl -s http://127.0.0.1:3413/v2/owner \
  -u "epic:$(cat ~/.epic/main/.api_secret)" \
  -d '{"jsonrpc":"2.0","method":"get_status","params":[],"id":1}' | epic_ok
```

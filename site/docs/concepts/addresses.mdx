# Addresses

`epic-wallet address` prints several identifiers, each with a different purpose. None of them appears in
the ledger; see [why there are no addresses](/concepts/mimblewimble#there-are-no-addresses).

| Identifier | Purpose |
| --- | --- |
| Epicbox address | Route slates to you through a store-and-forward relay |
| Payment proof address | Prove afterwards that you were the intended recipient |

The wallet also prints an onion address. That belongs to a transport this documentation does not cover;
see [what this version does not cover](/start#what-this-version-does-not-cover).

## Epicbox addresses

The format is:

```
<public_key>@<domain>[:<port>]
```

optionally prefixed with `epicbox://`.

The `public_key` is 52 base58 characters: a compressed secp256k1 public key in base58-check encoding,
with version bytes `[1, 0]` on mainnet and `[1, 136]` on floonet.

Two useful properties follow from that encoding:

**Typos are caught locally.** A corrupted address fails its checksum and the wallet rejects it before
sending anything. You do not need the network to discover an address is wrong.

**Mainnet and floonet addresses cannot be confused.** The version bytes differ, so a floonet address
will not parse as a mainnet one.

:::note
Usernet wallets emit mainnet-prefix addresses (`[1, 0]`). Only floonet gets a distinct prefix (`[1, 136]`).
:::

The domain defaults to `epicbox.epiccash.com` when omitted. Port 443 is the default and is not shown;
other ports are.

Because the identifier is a real public key, a relay can verify you own the address by asking you to
sign a challenge, without ever seeing your private key. See
[epicbox authentication](/api/epicbox#authentication).

:::note[One epicbox address per wallet]

The `epicbox_address_index` config key currently has no effect because every derivation uses index 0.
A wallet therefore has one effective epicbox address; the setting cannot provide per-user addresses.

:::

## Payment proof addresses

A separate key used to prove afterwards that a specific party was the intended recipient of a specific
transfer. It has to be arranged before the transfer, because the recipient signs the proof as part of
their round.

Confirm the wallet has a proof address before agreeing to supply a proof: `epic-wallet address` prints
it under this heading.

See [payment proofs](/concepts/payment-proofs). Requesting one requires the HTTP transport.

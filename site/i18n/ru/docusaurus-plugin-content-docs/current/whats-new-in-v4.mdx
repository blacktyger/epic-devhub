# Миграция с 3.x

Текущие релизы: узел **<Ver k="node" />**, кошелёк **<Ver k="wallet" />** и протокол epicbox **<Ver k="epicboxProtocol" />**.

## Изменения API {/* #api-changes */}

### `total_difficulty` — объект {/* #total_difficulty-is-an-object */}

Сложность отслеживается отдельно для каждого алгоритма доказательства работы:

```json
{
  "total_difficulty": {
    "cuckaroo": 0,
    "cuckatoo": 1234,
    "randomx": 5678,
    "progpow": 9012
  }
}
```

### Заголовки блоков описывают доказательства двумя полями {/* #block-headers-describe-proofs-with-two-fields */}

`proof` задаёт название алгоритма, а `solution` — размеченное объединение, форма которого зависит от него. В
версии 3.x одно скалярное поле содержало решение.

### Чтение выходов и транзакций кошелька поддерживает пагинацию {/* #wallet-output-and-transaction-reads-take-pagination */}

`retrieve_outputs` и `retrieve_txs` принимают `limit`, `offset` и `sort_order`. Передавайте их явно.

### `Status` получает поля supply {/* #status-gains-supply-fields */}

`supply` и `max_supply` — суммы в freemen. `blocks_to_next_halving` — количество блоков, при <Src repo="node" path="api/src/types.rs" line={102} />. Шаги эмиссии не являются
исключительно халвингами; см. [emission](/mining/emission).

### Ядра представлены в двух формах {/* #kernels-appear-in-two-shapes */}

`get_block` возвращает плоское ядро (kernel). `get_kernel` и `get_last_n_kernels` возвращают исходный тип с внешне размеченным
полем `features`.

## Изменения командной строки {/* #command-line-changes */}

Флаги изменились. `init -h` для текущего каталога теперь `-w`, `scan -h <height>` теперь `-s <height>`, а аргумент `taxes` узла —
`start_height`. Новые команды кошелька: `export_tx`, `import_tx` и `change_password`, а также `--slate_version` для команд перевода. Все команды и
флаги описаны в [configuration and CLI](/reference/cli).

Смесь алгоритмов в тестовых сетях задаётся ключом конфигурации, а не флагом командной строки. См.
[the block policy](/mining/proof-of-work#the-block-policy).

## Тулчейн и сборка {/* #toolchain-and-build */}

Каждый репозиторий фиксирует версию Rust, поэтому достаточно установить rustup — самостоятельно
фиксировать версию не нужно. Для сборки также требуются системные пакеты помимо тулчейна Rust; они
перечислены по платформам в [building from source](/guides/build).

## Изменения хранилища {/* #storage-changes */}

Кошелёк хранит данные в SQLite по пути `db/sqlite/epic.db` в режиме WAL, а его каталог Tor — `wallet_tor`. Всё, что читало
базу данных кошелька 3.x напрямую, требует переработки. Пути и ключи описаны в [wallet
configuration](/reference/wallet-config).

## Новое поведение {/* #new-behaviour */}

### Встроенный Tor {/* #bundled-tor */}

Сборка с `--features with-tor` загружает экспертный пакет Tor и проверяет его по зафиксированному дайджесту. В
релизных сборках эта функция не включена. См. [what this version does not cover](/start#what-this-version-does-not-cover).

### Epicbox подтверждает доставку {/* #epicbox-acknowledges-delivery */}

Протокол <Ver k="epicboxProtocol" /> добавляет подтверждение `Made` с идентификатором сообщения, так что слейт (slate)
помечается доставленным только после того, как получатель подтверждает его обработку. Совместимость
с клиентами до версии 3.5.2 сохранена. См. [the protocol](/api/epicbox).

### Подтверждение мемпула после публикации {/* #mempool-confirmation-after-posting */}

После публикации транзакции кошелёк отслеживает мемпул узла и фиксирует отдельное состояние при её
появлении там. Именно это ожидание является причиной того, что отправка может выглядеть зависшей —
подробнее в [the send appears to hang](/guides/stuck-transactions#case-3-the-send-appears-to-hang); кроме того, опубликованный перевод выходит из множества,
которое принимает `cancel_tx`, — подробнее в [cancelling has preconditions](/concepts/outputs-and-locking#cancelling-has-preconditions).

### Реализация релея Epicbox изменилась {/* #the-epicbox-relay-implementation-changed */}

Релей — `EpicCash/epic-epicbox-docker`, Node.js с вспомогательным модулем верификации на Rust. Топология развёртывания и
хранилище описаны в [the epicbox reference](/api/epicbox).

## Поведение, которое нужно проверить в вашей интеграции {/* #behaviour-to-check-in-your-integration */}

- **`tx_lock_outputs` обязателен** в ручной последовательности отправки. См. [what reserves outputs](/concepts/outputs-and-locking#what-reserves-outputs).
- **Epicbox конвертирует каждый слейт в V2**, что удаляет запрос доказательства платежа. См. [the
  transport comparison](/concepts/transports#comparison).
- **`change_password` удаляет резервную сид-фразу**, если не передан `--remove-backup`.
- **Значения по умолчанию для валидации синхронизации изменились.** `skip_pow_validation` по умолчанию равно `true`, а
  `disable_checkpoints` — `false`. В mainnet доказательство работы пропускается только до последней контрольной точки и
  полностью проверяется выше неё, а `disable_checkpoints` игнорируется. См. [node and wallet setup](/guides/mainnet-setup#sync-validation-settings).

## Изменения в 4.1.0 {/* #changes-in-410 */}

Узел и кошелёк версии 4.1.0 ужесточают аутентификацию. Интеграция, работавшая с 4.0.x, может начать
получать ответы 401.

- **Owner API кошелька требует HTTP Basic.** `/v3/owner` и `/v2/owner` принимают имя пользователя `epic` и
  содержимое `.owner_api_secret` в дополнение к токену v3. См. [owner access on the wallet](/api/authentication#owner-access-on-the-wallet).
- **`/v1` и `/v2/owner` узла закрыты по умолчанию.** При отсутствии настроенного секрета они возвращают 401,
  а не работают в открытом режиме. Без учётных данных отвечают только `GET /v1/version` и один вызов `get_status` типа
  plain. См. [the node credential](/api/authentication#the-node-credential).
- **Новый метод Foreign API `ready_for_txs`** сообщает, синхронизирован ли узел, без учётных данных. Кошелёк
  использует его вместо owner-метода `get_status`. См. [which method lives where](/api/node#which-json-rpc-method-lives-where).
- **Кошелёк значительно реже отправляет секрет узла.** Он никогда не отправляет его в `/v2/foreign`, поэтому
  узел с установленным `foreign_api_secret_path` не может его обслуживать. См. [the credential the wallet presents to the
  node](/api/authentication#the-credential-the-wallet-presents-to-the-node).
- **`/v1/kerneldownload` удалён.** См. [the v1 routes](/api/node#routes).
- **`disable_checkpoints` по умолчанию равен `false` и игнорируется на mainnet,** а новая контрольная точка на высоте
  блока <Ver k="lastCheckpointHeight" />, задающая <Ver k="checkpointCount" />, смещает конец пропускаемого диапазона. См. [настройки валидации
  синхронизации](/guides/mainnet-setup#sync-validation-settings).

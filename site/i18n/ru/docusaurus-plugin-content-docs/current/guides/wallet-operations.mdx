# Операции кошелька

Что делать с кошельком, который настроен и подключён к узлу. Всё здесь относится к mainnet, поэтому
флаг сети не указывается, и каждая команда, перемещающая средства, является реальной.

Предварительная настройка: [настройка узла и кошелька](/guides/mainnet-setup). Механика перевода та же, что вы уже
применяли на локальной цепочке в разделе [первый перевод](/guides/first-transfer).

## Чтение состояния кошелька {/* #read-what-the-wallet-knows */}

```bash
epic-wallet info
```

```
Total                   15.00000000
Immature Coinbase       0.00000000
Awaiting Confirmation   0.00000000
Locked by transaction   0.00000000
Currently Spendable     15.00000000
```

Суммы выводятся с 8 десятичными знаками, поскольку 1 EPIC равен <Ver k="epicBase" /> <Ver k="smallestUnit" />. Строки с нулевыми
значениями иногда скрываются, а не отображаются.

Разрыв между `Total` и `Currently Spendable` — нормальная ситуация, означающая одно из трёх: не прошла зрелость
coinbase, перевод выполняется и зарезервировал входы, либо не достигнут порог подтверждений. Раздел
[выходы и блокировка](/concepts/outputs-and-locking) объясняет, какой из случаев имеет место.

`--min_conf` задаёт порог подтверждений — минимальную глубину, которую должен иметь выход (output), прежде
чем кошелёк сочтёт его доступным к трате. Значение по умолчанию равно 10 и указывается ровно для
трёх подкоманд: `send` (<Src repo="wallet" path="src/cmd/wallet_args.rs" line={143} />), `pay` (<Src repo="wallet" path="src/cmd/wallet_args.rs" line={263} />) и `info` (<Src repo="wallet" path="src/cmd/wallet_args.rs" line={361} />). Ключа конфигурации нет, поэтому значение по
умолчанию применяется, если флаг не передан. Для `info` он изменяет значение `Currently Spendable`, которое выводит
сводка, — так можно проверить, что станет доступно при заданном пороге:

```bash
epic-wallet info --min_conf 1
```

Зрелость coinbase — отдельный порог на уровне консенсуса, на который этот флаг не влияет. См. раздел
[тайминг эмиссии](/mining/emission#timing).

```bash
epic-wallet txs
```

Детали по каждой транзакции. `Sent (Created)` со значением `Confirmed?` false — незавершённый перевод, удерживающий
зарезервированные входы. Столбец `From/To Address` заполняется только для переводов через epicbox; файловый и
HTTP-транспорт оставляют его пустым, поэтому по одному только журналу нельзя определить, кто вам
заплатил.

### Глубина подтверждения транзакции {/* #confirmation-depth-of-a-transaction */}

Глубина транзакции — это текущая высота блока цепочки минус высота, на которой кошелёк зафиксировал
её подтверждение. Кошелёк записывает эту высоту в журнал транзакций как `confirmation_height` (<Src repo="wallet" path="libwallet/src/types.rs" line={849} />), устанавливаемое
в момент, когда обновление обнаруживает выходы в цепочке (<Src repo="wallet" path="libwallet/src/internal/updater.rs" line={370} />). Значение равно `null` до тех пор,
пока `confirmed` не станет true. Высота цепочки берётся из `get_status` узла, поле `tip.height`.

Оба поля присутствуют в результате `retrieve_txs` Owner API. `epic-wallet txs` выводит высоту, а не глубину, поэтому
интеграция вычисляет разность самостоятельно.

## Автоматизация команд {/* #automating-these-commands */}

`epic-wallet` запрашивает пароль кошелька, когда он нужен команде. Два способа передать его без запроса:

**Через командную строку.** `-p` — глобальный флаг, поэтому он указывается перед подкомандой (<Src repo="wallet" path="src/cmd/wallet_args.rs" line={78} />).
Считывайте его из переменной окружения, а не вводите вручную, чтобы значение не попало в историю
оболочки:

```bash
epic-wallet -p "$EPIC_WALLET_PASSWORD" info
```

**Через Owner API.** `open_wallet` принимает пароль в качестве параметра и возвращает токен сессии для всех
последующих вызовов. Примеры клиентов считывают `EPIC_WALLET_PASSWORD` из переменной окружения и передают напрямую в
`open_wallet` — это и есть шаблон для копирования:

```python
wallet = EpicWallet()
wallet.open_wallet(password=os.environ["EPIC_WALLET_PASSWORD"])
```

## Получить {/* #receive */}

Тот, кто платит вам, нуждается в участии вашего кошелька, поскольку перевод Epic строится обеими
сторонами. Это означает необходимость слушателя либо файла слейта (slate), который вы обрабатываете
вручную.

```bash
epic-wallet listen -m epicbox -n
```

Удерживает подключение к epicbox-релею. Выведите адрес для передачи другим:

```bash
epic-wallet address
```

Адрес epicbox состоит из 52 символов base58: `@`, затем домен релея. Он маршрутизирует слейты к
вам. Это не аккаунт в цепочке, его нельзя найти в цепочке, и он не раскрывает ваш баланс.
Повреждённый адрес не проходит контрольную сумму локально, до отправки чего-либо.

Слейт, отправленный в то время, когда вы были офлайн, доставляется при повторном подключении. Два
отдельных ограничения определяют, как долго релей хранит слейт, причём меньшее из них — не срок
хранения, поэтому отправитель, чей перевод так и не прошёл, отменяет его и повторяет попытку, а не
ждёт бесконечно. См. раздел [доставка и её ограничения](/api/epicbox#delivery-and-its-limits).

Для обработки файла слейта вместо прослушивания:

```bash
epic-wallet receive -m file -i slate.tx
# записывает slate.tx.response, который возвращается отправителю
```

## Отправить {/* #send */}

```bash
epic-wallet send -m epicbox -d <recipient-address> <amount>
```

<Risk level="spend" /> Это резервирует ваши входы немедленно, до того как получатель что-либо сделал. См. раздел [что
резервирует выходы](/concepts/outputs-and-locking#what-reserves-outputs).

Запросить комиссию перед подтверждением:

```bash
epic-wallet send --estimate_only -m epicbox -d <recipient-address> <amount>
```

Комиссии зависят от количества входов и выходов, а не от фиксированной ставки. Консолидация
множества мелких выходов увеличивает оценку.

После публикации команда опрашивает мемпул узла, чтобы подтвердить получение транзакции; см.
[отправка зависает](/guides/stuck-transactions#case-3-the-send-appears-to-hang). При использовании `-m epicbox` обеим сторонам нужна подписка, так как подписанный с
обеих сторон слейт (slate) возвращается через релей, а собственный слушатель финализирует его.

Epicbox использует slate V2 и не может передавать доказательство платежа. См. [транспорты](/concepts/transports#comparison).

## Повторная публикация завершённого перевода без подтверждения {/* #repost-a-completed-transfer-that-never-confirmed */}

Финализированная транзакция записывается в `wallet_data/saved_txs/` до публикации, поэтому её можно опубликовать
повторно без пересборки. Это актуально, когда перевод завершил оба раунда, но публикация не достигла
узла.

```bash
epic-wallet txs                        # найти id неподтверждённой записи Sent
epic-wallet repost -i <id>
```

| Флаг | Эффект |
| --- | --- |
| `-i <id>` | Идентификатор лога транзакции с сохранённой транзакцией |
| `-m <file>` | Записать транзакцию в файл вместо публикации |
| `-f` | Опубликовать напрямую, минуя Dandelion релей |

Объявлено в <Src repo="wallet" path="src/cmd/wallet_args.rs" line={335} />. `repost` требует сохранённого объекта транзакции, поэтому работает только для
переводов, у которых запись `saved_txs/` ещё присутствует. Кошелёк, восстановленный только из фразы, таких
записей не имеет.

## Отмена перевода, который не может завершиться {/* #cancel-a-transfer-that-cannot-complete */}

<Risk level="destructive" /> Отмена освобождает зарезервированные входы и прерывает перевод.

```bash
epic-wallet txs                 # найти id незавершённого перевода
epic-wallet cancel -i <id>
```

См. [условия отмены](/concepts/outputs-and-locking#cancelling-has-preconditions) и [диагностика застрявшей транзакции](/guides/stuck-transactions) — что делать, когда `cancel`
отказывает.

## Восстановление кошелька, расходящегося с цепочкой {/* #repair-a-wallet-that-disagrees-with-the-chain */}

```bash
epic-wallet scan
```

Пересканирует цепочку по вашим ключам и перестраивает локальное представление ваших выходов.

Заблокированные выходы при этом не освобождаются, так как блокировка — локальная запись, о которой
цепочка ничего не знает. См. [что их освобождает](/concepts/outputs-and-locking#what-releases-them).

:::warning[`scan --delete_unconfirmed` is a different thing]

Разблокирует заблокированные выходы и удаляет их записи в журнале транзакций, то есть удаляет записи
вместо их перестройки. Сначала используйте обычный `scan`.

:::

## Аккаунты {/* #accounts */}

Аккаунт — это метка, привязанная к одному пути деривации внутри единственного сида кошелька. В
каждом кошельке есть один аккаунт с именем `default`.

```bash
epic-wallet account            # вывести все метки с путями деривации
epic-wallet account -c savings # создать один
epic-wallet -a savings info    # выполнить любую команду для него
```

`-a` указывается перед субкомандой и по умолчанию равен `default`. Он выбирает аккаунт для данного
вызова, а также определяет, с какого аккаунта `send` тратит средства и на какой аккаунт зачисляет `receive`
или слушатель epicbox.

Аккаунты совместно используют фразу восстановления, пароль и резервную копию, поэтому резервируются
вместе. См. [аккаунты](/concepts/accounts) — схему деривации и то, что каждый аккаунт хранит отдельно.

## Изменить пароль {/* #change-the-password */}

```bash
epic-wallet change_password
```

Сид перешифровывается с новым паролем, фраза при этом не меняется. `wallet.seed.bak` записывается, а затем
удаляется; передайте `--remove-backup`, чтобы сохранить его. См. [смена пароля](/guides/backup-and-restore#changing-your-password).

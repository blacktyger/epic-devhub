# Настройка узла и кошелька для mainnet

Mainnet — это реальная ценность. Всё здесь предполагает, что вы уже прошли локальную цепочку в
[запустить локальную сеть](/guides/local-network) и [первый перевод](/guides/first-transfer), потому что механика идентична, а последствия —
нет.

Два процесса. Узел, который валидирует и ретранслирует цепочку, и кошелёк, который хранит ключи и
запрашивает у узла состояние сети. Узел необходим. Майнинг не обязателен.

## 1. Запустить узел {/* #1-start-the-node */}

Mainnet — сеть по умолчанию, поэтому флаг не нужен:

```bash
epic
```

Узел записывает `epic-server.toml` при первом запуске и читает его в дальнейшем. Редактирование этого файла —
стандартный способ изменить поведение, поскольку большинство настроек существуют только как ключи
конфигурации, а не как флаги командной строки. Каждый ключ требует перезапуска.

Убедитесь, что узел запущен. Интерфейс владельца требует аутентификации, секрет создаётся
автоматически:

<Tabs groupId="os">
<TabItem value="linux" label="Linux и macOS">

```bash
curl -s -u epic:$(cat ~/.epic/main/.api_secret) -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","method":"get_status","params":[],"id":1}' \
  http://127.0.0.1:3413/v2/owner
```

</TabItem>
<TabItem value="win" label="Windows">

```powershell
$secret = (Get-Content "$HOME\.epic\main\.api_secret" -First 1).Trim()
$body = '{"jsonrpc":"2.0","method":"get_status","params":[],"id":1}'
Invoke-RestMethod -Uri 'http://127.0.0.1:3413/v2/owner' -Method Post `
  -ContentType 'application/json' -Body $body `
  -Authentication Basic -Credential (
    [PSCredential]::new('epic', (ConvertTo-SecureString $secret -AsPlainText -Force))
  ) -AllowUnencryptedAuthentication
```

</TabItem>
</Tabs>

Первая синхронизация загружает и валидирует всю цепочку. Ожидайте, что это займёт некоторое время и
потребует реального дискового пространства.

### Порты {/* #ports */}

| Порт | Назначение | Привязка по умолчанию |
| --- | --- | --- |
| <Ver k="ports.nodeApi" /> | HTTP API | `127.0.0.1` |
| <Ver k="ports.nodeP2p" /> | P2P | Все интерфейсы |
| <Ver k="ports.stratum" /> | Stratum-сервер майнинга | `127.0.0.1`, отключено по умолчанию |

Только P2P-порт должен быть доступен извне. Оставьте API на loopback и прочитайте [аутентификация и
TLS](/api/authentication) перед изменением этого. Каждый порт и сетевое смещение описаны в [справочнике CLI](/reference/cli#ports).

### Настройки валидации синхронизации {/* #sync-validation-settings */}

`skip_pow_validation` и `disable_checkpoints` оба по умолчанию равны `true`. Это оптимизация скорости синхронизации, а не ослабленное
значение по умолчанию.

| Где находится блок | Выполняемая проверка |
| --- | --- |
| Внутри диапазона с контрольной точкой | Хеш заголовка сравнивается с жёстко заданной контрольной точкой. Несовпадение прерывает синхронизацию. Доказательство работы пропускается |
| За контрольными точками, более чем на <Ver k="powVerificationThreshold" /> блоков позади вершины цепочки | Доказательство работы пропускается |
| В пределах <Ver k="powVerificationThreshold" /> блоков от вершины цепочки | **Полное доказательство работы, всегда, независимо от этих настроек** |

В узел скомпилировано <Ver k="checkpointCount" /> контрольных сумм в <Src repo="node" path="chain/src/types.rs" line={432} />. Код — <Fn repo="node" path="chain/src/chain.rs" line={1567} name="check_header_against_checkpoints" />, решение о пропуске — в <Src repo="node" path="servers/src/common/adapters.rs" line={728} />, нижняя
граница — <Fn repo="node" path="servers/src/common/adapters.rs" line={45} kind="const" name="POW_VERIFICATION_THRESHOLD" />.

Установите оба в `false`, чтобы самостоятельно верифицировать всё историческое доказательство работы.
Это потребует значительно более долгой начальной синхронизации.

### Что хранит узел {/* #what-the-node-stores */}

`chain_data`, файл конфигурации, файлы журналов и API secret. `chain_data` — крупный элемент, и он одноразовый: его
удаление стоит лишь повторной синхронизации и ничего больше. Узел не хранит ключей, поэтому ничто в
его каталоге данных не требует резервного копирования.

## 2. Создать кошелёк {/* #2-create-the-wallet */}

```bash
epic-wallet init
```

Вам будет предложено задать пароль, и будет показана фраза восстановления.

:::danger[Write the recovery phrase down before continuing]

Фраза — единственное, что позволяет восстановить ваши средства. Она показывается один раз здесь, а
впоследствии только через `epic-wallet recover`, которому требуется пароль.

:::

| Команда | Эффект |
| --- | --- |
| `epic-wallet init` | Создать кошелёк в расположении по умолчанию, `~/.epic/main` |
| `epic-wallet init -w` | Создать в текущем каталоге. Флаг не принимает значения |
| `epic-wallet init -r` | Восстановить из существующей фразы восстановления |

`init -r` отказывается запускаться, если файл сида уже существует, поэтому восстановление в каталог, в
котором уже есть кошелёк, требует предварительного перемещения этого кошелька. См. [резервное
копирование и восстановление](/guides/backup-and-restore).

### Отключить слушатель Tor {/* #turn-off-the-tor-listener */}

Кошелёк по умолчанию устанавливает `use_tor_listener` в `true` и ожидает бинарный файл Tor, который не поставляется
в архивах релиза, поэтому `epic-wallet listen` запускает фоновый поток, который завершается с ошибкой. Два способа
отключить это, один из которых применяется на уровне команды:

```toml title="epic-wallet.toml"
[tor]
use_tor_listener = false
```

```bash
epic-wallet listen -n
```

`-n` объявляется только в `listen` (<Src repo="wallet" path="src/cmd/wallet_args.rs" line={123} />), поэтому его нужно повторять при каждом `listen`. Ключ
конфигурации применяется ко всем командам в этом каталоге кошелька и является предпочтительной
настройкой. Ни один из вариантов не влияет на использование Tor узлом.

### Что хранит кошелёк {/* #what-the-wallet-stores */}

[Резервное копирование и восстановление](/guides/backup-and-restore#what-to-back-up) перечисляет все файлы в каталоге кошелька, что они
содержат и нужно ли их резервировать. Фраза восстановления восстанавливает средства, но не историю.
Записи транзакций, метки аккаунтов и записи доказательств платежей хранятся только в базе данных, и
ничто в цепочке не может их восстановить.

### Порты, открываемые кошельком {/* #ports-the-wallet-opens */}

`epic-wallet listen` открывает Foreign API на <Ver k="ports.walletForeign" />, а `epic-wallet owner_api` открывает Owner API на <Ver k="ports.walletOwner" />. Порт Foreign API
определяется сетью; порт Owner API равен <Ver k="ports.walletOwner" /> в любой сети, поэтому второй кошелёк на той же машине
будет конфликтовать с ним независимо от того, в какой цепочке он работает. Переопределите `owner_api_listen_port`.
Полный список — в [справочнике CLI](/reference/cli#ports).

## 3. Указать кошельку адрес узла {/* #3-point-the-wallet-at-the-node */}

Кошелёк по умолчанию подключается к узлу на loopback на порту <Ver k="ports.nodeApi" /> и в стандартной конфигурации
разрешает API secret узла из того же файла, который создал узел. Настройка не требуется.

Два случая меняют это. Если вы переместили любой из каталогов, установите `node_api_secret_path` в [учётные данные,
которые кошелёк предъявляет узлу](/api/authentication#the-credential-the-wallet-presents-to-the-node). Если нужен другой узел, установите `check_node_api_http_addr` в `epic-wallet.toml`.

```bash
epic-wallet info
```

Нулевой баланс без ошибки означает, что кошелёк достиг узла и узел ответил. Код 401 означает, что
они расходятся в секрете.

Кошелёк, направленный на публичный узел, работает. Этот узел видит, о каких выходах (outputs)
спрашивает кошелёк, а кошелёк не валидирует полученное состояние цепочки.

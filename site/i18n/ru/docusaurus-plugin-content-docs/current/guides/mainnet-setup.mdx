# Настройка узла и кошелька для mainnet

Mainnet работает с реальными ценностями. Всё описанное здесь предполагает, что вы уже прошли
локальную цепочку в [запуске локальной сети](/guides/local-network) и [первом переводе](/guides/first-transfer), поскольку механика
идентична, а последствия — нет.

Два процесса. Узел, который валидирует и ретранслирует цепочку, и кошелёк, который хранит ключи и
запрашивает у узла состояние сети. Узел необходим. Майнинг не обязателен.

## 1. Запустить узел {/* #1-start-the-node */}

Mainnet — сеть по умолчанию, поэтому флаг не нужен:

```bash
epic
```

Узел записывает `epic-server.toml` при первом запуске и читает его при всех последующих. Редактирование этого
файла — стандартный способ изменить поведение, поскольку большинство настроек существуют только как
ключи конфигурации, а не как флаги командной строки. Каждый ключ требует перезапуска.

Убедитесь, что узел запущен. Интерфейс владельца требует аутентификации, секрет создаётся
автоматически:

<Tabs groupId="os">
<TabItem value="linux" label="Linux и macOS">

```bash
curl -s -u epic:$(cat ~/.epic/main/.api_secret) -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","method":"get_status","params":[],"id":1}' \
  http://127.0.0.1:3413/v2/owner
```

</TabItem>
<TabItem value="win" label="Windows">

```powershell
$secret = (Get-Content "$HOME\.epic\main\.api_secret" -First 1).Trim()
$body = '{"jsonrpc":"2.0","method":"get_status","params":[],"id":1}'
Invoke-RestMethod -Uri 'http://127.0.0.1:3413/v2/owner' -Method Post `
  -ContentType 'application/json' -Body $body `
  -Authentication Basic -Credential (
    [PSCredential]::new('epic', (ConvertTo-SecureString $secret -AsPlainText -Force))
  ) -AllowUnencryptedAuthentication
```

</TabItem>
</Tabs>

Первая синхронизация загружает и валидирует всю цепочку. Ожидайте, что это займёт некоторое время и
потребует реального дискового пространства.

### Порты {/* #ports */}

| Порт | Назначение | Привязка по умолчанию |
| --- | --- | --- |
| <Ver k="ports.nodeApi" /> | HTTP API | `127.0.0.1` |
| <Ver k="ports.nodeP2p" /> | P2P | Все интерфейсы |
| <Ver k="ports.stratum" /> | Stratum-сервер майнинга | `127.0.0.1`, по умолчанию отключено |

Только P2P-порт должен быть доступен извне. Оставьте API на loopback и прочитайте [аутентификацию и
TLS](/api/authentication) перед тем, как это менять. Каждый порт и сетевое смещение описаны в [справочнике CLI](/reference/cli#ports).

### Настройки валидации синхронизации {/* #sync-validation-settings */}

`skip_pow_validation` по умолчанию равно `true`, а `disable_checkpoints` — `false`. Пропуск доказательства работы внутри диапазона с
чекпоинтами — это оптимизация скорости синхронизации, а не ослабление настроек по умолчанию:
пропускаемый диапазон заканчивается на жёстко заданном чекпоинте, хэш которого должен совпасть, и
каждый заголовок в нём ссылается на этот чекпоинт. Сравниваются по хэшу только заголовки на высотах
<Ver k="checkpointCount" /> чекпоинтов; заголовки между ними — нет.

| Где находится блок | Валидация выполняется на mainnet |
| --- | --- |
| В диапазоне контрольных точек, до высоты <Ver k="lastCheckpointHeight" /> | Заголовок на высоте контрольной точки сравнивается с захардкоженным хешем; несовпадение прерывает синхронизацию. Доказательство работы пропускается, пока `skip_pow_validation` равно `true` |
| Выше последнего чекпоинта | **Полное доказательство работы, всегда, независимо от этих настроек** |

Пакет заголовков считается прошедшим чекпоинт только в том случае, если каждый заголовок в нём
прошёл его.

В узел скомпилировано <Ver k="checkpointCount" /> чекпоинтов, в <Src repo="node" path="chain/src/types.rs" line={432} />. Код — <Fn repo="node" path="chain/src/chain.rs" line={1545} name="check_header_against_checkpoints" />, решение о пропуске — <Fn repo="node" path="servers/src/common/adapters.rs" line={51} name="should_skip_pow" />; при запуске на
mainnet узел записывает в лог, какая политика применяется.

`disable_checkpoints` игнорируется на mainnet. В тестовой сети, при `skip_pow_validation` также `true`, он расширяет пропуск за пределы
последнего чекпоинта для блоков, находящихся более чем на <Ver k="powVerificationThreshold" /> ниже вершины цепочки (<Fn repo="node" path="servers/src/common/adapters.rs" line={45} kind="const" name="POW_VERIFICATION_THRESHOLD" />).

Установите `skip_pow_validation = false`, чтобы самостоятельно проверить всё историческое доказательство работы. Это
потребует значительно более долгой начальной синхронизации.

### Что хранит узел {/* #what-the-node-stores */}

`chain_data`, файл конфигурации, файлы логов и API-секрет. `chain_data` — крупный элемент, и он одноразовый: его
удаление обходится пересинхронизацией и ничем больше. Узел не хранит ключей, поэтому ничто в его
каталоге данных не требует резервного копирования.

## 2. Создать кошелёк {/* #2-create-the-wallet */}

```bash
epic-wallet init
```

Вам будет предложено задать пароль, и будет показана фраза восстановления.

:::danger[Write the recovery phrase down before continuing]

Фраза — единственное, что позволяет восстановить ваши средства. Она отображается здесь один раз, а
впоследствии — только через `epic-wallet recover`, которому нужен пароль.

:::

| Команда | Эффект |
| --- | --- |
| `epic-wallet init` | Создать кошелёк в расположении по умолчанию, `~/.epic/main` |
| `epic-wallet init -w` | Создать в текущем каталоге. Флаг не принимает значения |
| `epic-wallet init -r` | Восстановить из существующей фразы восстановления |

`init -r` отказывается запускаться, если файл сида уже существует, поэтому восстановление в каталог, в
котором уже есть кошелёк, требует предварительного перемещения этого кошелька. См. [резервное
копирование и восстановление](/guides/backup-and-restore).

### Отключить слушатель Tor {/* #turn-off-the-tor-listener */}

Кошелёк по умолчанию устанавливает `use_tor_listener` в `true` и ожидает бинарный файл Tor, который в архивах релиза
не поставляется, поэтому `epic-wallet listen` запускает фоновый поток, который завершается с ошибкой. Есть два
способа отключить это, и один из них действует на уровне отдельной команды:

```toml title="epic-wallet.toml"
[tor]
use_tor_listener = false
```

```bash
epic-wallet listen -n
```

`-n` объявляется только в `listen` (<Src repo="wallet" path="src/cmd/wallet_args.rs" line={123} />), поэтому его нужно повторять при каждом `listen`. Ключ
конфигурации применяется ко всем командам в данном каталоге кошелька и является предпочтительной
настройкой. Ни один из вариантов не влияет на использование Tor узлом.

### Что хранит кошелёк {/* #what-the-wallet-stores */}

[Резервное копирование и восстановление](/guides/backup-and-restore#what-to-back-up) перечисляет все файлы в каталоге кошелька, что они
содержат и нужно ли их резервировать. Фраза восстановления восстанавливает ваши средства, но не
историю. Записи транзакций, метки аккаунтов и записи доказательств платежа хранятся только в базе
данных, и ничто в цепочке не может их восстановить.

### Порты, открываемые кошельком {/* #ports-the-wallet-opens */}

`epic-wallet listen` открывает Foreign API на <Ver k="ports.walletForeign" />, а `epic-wallet owner_api` открывает Owner API на <Ver k="ports.walletOwner" />. Порт Foreign API
определяется сетью; порт Owner API равен <Ver k="ports.walletOwner" /> в любой сети, поэтому второй кошелёк на той же машине
будет конфликтовать с ним вне зависимости от того, в какой цепочке он работает. Переопределите `owner_api_listen_port`.
Полный список — в [справочнике CLI](/reference/cli#ports).

## 3. Указать кошельку адрес узла {/* #3-point-the-wallet-at-the-node */}

Кошелёк по умолчанию подключается к узлу на loopback на порту <Ver k="ports.nodeApi" />. Настройка не требуется.

Вызовы кошелька идут к поверхностям узла, не требующим учётных данных, поэтому перемещение любого из
каталогов не нарушает работу. `node_api_secret_path` важен только для поиска onion-адреса Tor; см. [учётные данные,
которые кошелёк предъявляет узлу](/api/authentication#the-credential-the-wallet-presents-to-the-node). Чтобы использовать другой узел, установите `check_node_api_http_addr` в `epic-wallet.toml`.

```bash
epic-wallet info
```

Нулевой баланс без ошибки означает, что кошелёк достиг узла и узел ответил. Код 401 означает, что у
узла установлен `foreign_api_secret_path`, с которым epic-wallet <Ver k="wallet" /> не может работать. Судя по коду, узел старше <Ver k="node" /> с
API-секретом также ответит 401; эта комбинация не тестировалась.

Кошелёк, направленный на публичный узел, работает. Этот узел видит, о каких выходах (outputs)
спрашивает кошелёк, а кошелёк не валидирует полученное состояние цепочки.

# Адреса

`epic-wallet address` выводит несколько идентификаторов, каждый из которых служит своей цели. Ни один из них не
фигурирует в реестре; см. [почему адресов нет](/concepts/mimblewimble#there-are-no-addresses).

| Идентификатор | Назначение |
| --- | --- |
| Адрес Epicbox | Маршрутизировать слейты (slate) через релей с хранением и пересылкой |
| Адрес доказательства платежа | Подтвердить впоследствии, что вы были целевым получателем |

Кошелёк также выводит onion-адрес, используемый транспортом Tor.

## Epicbox-адреса {/* #epicbox-addresses */}

Формат:

```text
<public_key>@<domain>[:<port>]
```

с необязательным префиксом `epicbox://`.

`public_key` — это 52 символа base58, сжатый публичный ключ secp256k1 в кодировке base58-check с байтами
версии `[1, 0]` в mainnet и `[1, 136]` в floonet.

Из этой кодировки следуют два свойства. Повреждённый адрес не проходит контрольную сумму, и кошелёк
отклоняет его локально, не обращаясь к сети; что это защищает, а что нет — рассмотрено в [адресов
нет](/concepts/mimblewimble#there-are-no-addresses). Адреса mainnet и floonet не перепутать: адрес floonet не разбирается как адрес mainnet.

:::note
Кошельки usernet выдают адреса с префиксом mainnet (`[1, 0]`). Только floonet получает отдельный префикс
(`[1, 136]`).
:::

Домен по умолчанию равен `epicbox.epiccash.com`, если не указан. Порт 443 является значением по умолчанию и не
отображается; остальные порты отображаются.

Поскольку идентификатор является настоящим публичным ключом, релей может проверить владение адресом,
попросив подписать вызов, не видя при этом приватного ключа. См. [аутентификация epicbox](/api/epicbox#authentication).

:::note[One epicbox address per account]

Каждое производное значение epicbox использует индекс 0, поэтому у кошелька один epicbox-адрес на
каждый хранимый аккаунт. Ключ конфигурации `epicbox_address_index` зарезервирован.

:::

## Адреса доказательства платежа {/* #payment-proof-addresses */}

Отдельный ключ, используемый для последующего доказательства того, что конкретная сторона являлась
предполагаемым получателем конкретного перевода. Его необходимо согласовать до перевода, поскольку
получатель подписывает доказательство в рамках своего раунда. `epic-wallet address` выводит его под этим заголовком.

См. [доказательства платежа](/concepts/payment-proofs) и [выбор транспорта](/concepts/payment-proofs#choose-the-transport-accordingly) для маршрутов, по которым они передаются.

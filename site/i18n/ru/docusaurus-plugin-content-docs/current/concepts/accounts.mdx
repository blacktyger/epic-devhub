# Аккаунты

Аккаунт — это метка, привязанная к одному пути деривации BIP32 внутри единственного сида кошелька.
Кошелёк хранит столько аккаунтов, сколько вы создадите; один с именем `default` существует с момента
инициализации кошелька.

Запись состоит из двух полей: метки и родительского пути деривации (<Src repo="wallet" path="libwallet/src/types.rs" line={992} />). Метка является ключом
хранения (<Src repo="wallet" path="impls/src/backends/lmdb.rs" line={823} />), поэтому после создания она неизменна. Всё, что кошелёк хранит о монетах,
индексируется по пути.

## Что входит в аккаунт {/* #what-belongs-to-an-account */}

| Относится к одному аккаунту | Общее для всего кошелька |
| --- | --- |
| Выходы и вычисленный из них баланс | Файл сида и фраза восстановления |
| Записи лога транзакций, нумерация с 0 в каждом аккаунте | Пароль |
| Следующий индекс дочерней деривации | Финализированные транзакции в `saved_txs/` |
| Последняя подтверждённая высота | Кэш слейтов (slate) в процессе обработки |
| Адреса epicbox и доказательства платежа | Высота последнего просканированного блока |

Сводка баланса, список выходов (outputs) и список транзакций — всё это читается из одного аккаунта
(<Src repo="wallet" path="libwallet/src/internal/updater.rs" line={479} />). Идентификаторы журнала транзакций начинаются с 0 для каждого аккаунта (<Src repo="wallet" path="impls/src/backends/lmdb.rs" line={721} />), поэтому
идентификатор уникален только внутри аккаунта, которому он принадлежит.

`epic-wallet address` выводит идентификаторы одного аккаунта, и у каждого аккаунта есть свой (<Src repo="wallet" path="controller/src/command.rs" line={1360} />). См.
[addresses](/concepts/addresses).

## Деривация {/* #derivation */}

`default` — это идентификатор глубины 2, у которого все дочерние индексы равны нулю. Аккаунт *n* берёт
наибольший существующий первый индекс и прибавляет единицу (<Src repo="wallet" path="libwallet/src/internal/keys.rs" line={81} />), поэтому пути выделяются в порядке
создания и никогда не используются повторно.

Метод `accounts` возвращает метку и идентификатор пути в виде hex: один байт глубины, за которым следуют
четыре дочерних индекса в формате big-endian:

```json
[
  {
    "label": "default",
    "path": "0200000000000000000000000000000000"
  }
]
```

Снято с кошелька, работающего на <Ver k="wallet" />, 2026-08-26. Аккаунт, созданный вторым, возвращает
`0200000001000000000000000000000000`
(<Src repo="wallet" path="api/src/owner_rpc_s.rs" line={99} />).

Под каждым путём аккаунта располагаются две ветви. Ключи выходов (outputs) — `m/<n>/0/<index>`, ключи адресов —
`m/<n>/1/<index>`, хешированные через blake2b в секрет (secret) secp256k1 (<Src repo="wallet" path="libwallet/src/address.rs" line={31} />). Инструмент, владеющий сидом,
может вывести оба для любого аккаунта без базы данных кошелька. Метка — единственное, что хранится
только в базе данных.

## Из командной строки {/* #from-the-command-line */}

```bash
epic-wallet account                 # вывести все метки с путями деривации
epic-wallet account -c savings      # создать один
epic-wallet -a savings info         # выполнить любую команду для него
```

`-a` по умолчанию равно `default` (<Src repo="wallet" path="src/cmd/wallet_args.rs" line={81} />) и вступает в силу при открытии кошелька, поэтому выбирает
аккаунт для данного вызова. Листинг выводит два столбца: имя и родительский путь деривации BIP-32
(<Src repo="wallet" path="controller/src/display.rs" line={431} />).

## Какой аккаунт использует перевод {/* #which-account-a-transfer-uses */}

**Отправка** тратит средства из аккаунта, выбранного `-a`. В Owner API `src_acct_name` в `InitTxArgs` задаёт его для
одного вызова, а метка, отсутствующая в `accounts`, разрешается в активный аккаунт (<Src repo="wallet" path="libwallet/src/api_impl/owner.rs" line={383} />). Передавайте
метку, которую вернул метод `accounts`.

**Получение через file или http** зачисляет средства на аккаунт, выбранный `-a`. Foreign API
принимает его как `dest_acct_name` в `receive_tx`.

**Получение через epicbox** зачисляет средства на аккаунт, который был активен в момент открытия
кошелька слушателем (<Src repo="wallet" path="impls/src/adapters/epicbox.rs" line={513} />). Этот слушатель подписывается с адресом данного аккаунта, поэтому один
процесс обслуживает один аккаунт.

**Перемещение средств между двумя аккаунтами одного кошелька** использует транспорт `self`, где `-d`
задаёт аккаунт назначения:

```bash
epic-wallet -a savings send -m self -d default 1.5
```

См. [transports](/concepts/transports#self).

## Обновление и сканирование {/* #refreshing-and-scanning */}

`refresh_from_node` обновляет активный аккаунт (<Src repo="wallet" path="libwallet/src/internal/updater.rs" line={245} />). `scan` обходит все аккаунты, поскольку восстанавливает выходы
(outputs) по пути деривации, который несёт каждый из них (<Src repo="wallet" path="libwallet/src/internal/scan.rs" line={376} />). Курсор сканирования является общим
для всего кошелька, тогда как последняя подтверждённая высота блока хранится отдельно для каждого
аккаунта; после сканирования высота каждого аккаунта устанавливается по его собственным выходам.

## После восстановления {/* #after-a-recovery */}

Кошелёк, восстановленный из фразы, восстанавливает пути деривации, но не метки. `default` сохраняет своё
имя, а каждый другой обнаруженный путь получает метку `account_1`, `account_2` и так далее в порядке обнаружения
(<Src repo="wallet" path="libwallet/src/internal/scan.rs" line={512} />). Средства попадают в ту ветвь, из которой они были выведены.

См. [what recovery does not bring back](/guides/backup-and-restore#what-recovery-does-not-bring-back).

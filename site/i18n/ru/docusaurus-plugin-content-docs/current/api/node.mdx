# Node API

Узел обслуживает JSON-RPC 2.0 на одном слушателе, привязанном к `127.0.0.1` порту <Ver k="ports.nodeApi" /> по умолчанию,
разделённом на две поверхности.

| Поверхность | Путь | Назначение |
| --- | --- | --- |
| Owner | `/v2/owner` | Администрирование узла, восемь методов |
| Foreign | `/v2/foreign` | Чтение цепочки, отправка транзакций, шаблоны блоков, <Ver k="foreignApiMethods" /> методов |

Учётные данные и то, какая из поверхностей их требует, описаны один раз в разделе [аутентификация и
TLS](/api/authentication).

Тот же слушатель также обслуживает REST-поверхность по адресу `/v1`. См. [REST-поверхность v1](#the-v1-rest-surface).

## Какой метод JSON-RPC на каком интерфейсе {/* #which-json-rpc-method-lives-where */}

`/v2/owner` — только администрирование узла:

`get_status`, `validate_chain`, `compact_chain`, `get_peers`, `get_connected_peers`, `ban_peer`, `unban_peer`, `get_onion_addresses`.

`/v2/foreign` — всё остальное, включая любое чтение цепочки и отправку транзакций:

`ready_for_txs`, `get_header`, `get_block`, `get_blocks`, `get_tip`, `get_version`, `get_kernel`, `get_last_n_kernels`, `get_outputs`, `get_unspent_outputs`, `get_pmmr_indices`, `get_pool_size`, `get_stempool_size`, `get_unconfirmed_transactions`, `push_transaction`, `get_block_template`,
`finalize_block_template`, `submit_block`.

Таким образом, чтение блока — это вызов foreign-поверхности, и при установке по умолчанию он не
требует учётных данных:

```bash
curl -s -d '{"jsonrpc":"2.0","method":"get_tip","params":[],"id":1}' \
  http://127.0.0.1:3413/v2/foreign
```

Проверка синхронизации узла — тоже вызов foreign-поверхности. `ready_for_txs` возвращает `{"ready_for_txs": true}` только когда
состояние синхронизации равно `no_sync`, в противном случае — `false`, и не требует учётных данных:

```bash
curl -s -d '{"jsonrpc":"2.0","method":"ready_for_txs","params":[],"id":1}' \
  http://127.0.0.1:3413/v2/foreign
```

Полный статус с высотой, пирами и именованным состоянием синхронизации доступен через `get_status` на
owner-поверхности. Обычно требуются [учётные данные узла](/api/authentication#the-node-credential), но один простой вызов `get_status`
обрабатывается без них.

## Формы ответов {/* #response-shapes */}

`total_difficulty` — объект с ключами по алгоритму доказательства работы, а не целое число:

```json
{
  "total_difficulty": {
    "cuckaroo": 0,
    "cuckatoo": 1234,
    "randomx": 5678,
    "progpow": 9012
  }
}
```

Заголовки блоков описывают своё доказательство двумя полями: `proof` — строка с именем алгоритма, и
`solution` — размеченное объединение (tagged union), форма которого зависит от алгоритма.

`Status` содержит `supply` и `max_supply` в целых EPIC, а не в freemen, и `blocks_to_next_halving` как количество блоков. Не все ступени
награды являются халвингами; см. [эмиссия](/mining/emission).

Ядра (kernel) возвращаются в двух формах в зависимости от метода. `get_block` возвращает плоскую форму,
тогда как `get_kernel` и `get_last_n_kernels` возвращают сырой тип с внешне размеченным полем `features`. Обрабатывайте обе формы.

## Майнинг через HTTP {/* #mining-over-http */}

Foreign-поверхность предлагает трёхшаговый процесс отправки блока как альтернативу Stratum: `get_block_template`,
`finalize_block_template`, `submit_block`. Это JSON-RPC поверх HTTP. См. [Stratum](/mining/stratum).

## REST-интерфейс v1 {/* #the-v1-rest-surface */}

Узел обслуживает REST по адресу `/v1` и JSON-RPC по адресу `/v2`, в одном процессе на одном порту.
Номера обозначают два стиля интерфейса, а не два поколения: `/v1` зарегистрирован на <Src repo="node" path="api/src/handlers.rs" line={692} />, `/v2` — на
<Src repo="node" path="api/src/handlers.rs" line={132} /> и <Src repo="node" path="api/src/handlers.rs" line={152} />.

Разница в том, где указывается имя операции.

|  | `/v1` | `/v2` |
| --- | --- | --- |
| Стиль | REST | JSON-RPC 2.0 |
| Операция задаётся | URL-путём | полем `method` в теле запроса |
| HTTP-метод | `GET`, `POST` для изменений | `POST` |
| URL | один на операцию | `/v2/foreign`, `/v2/owner`, `/v2/tor` |
| Результат | тело ответа | тело ответа внутри `result.Ok` |
| Учётные данные | Basic auth для префикса `/v1`, кроме `GET /v1/version` | по поверхности |

Обе поверхности возвращают одинаковые данные. `GET /v1/status` и `get_status` на `/v2/owner` выдают идентичные тела ответов,
поэтому [страницы JSON-RPC](#full-method-reference) документируют формы ответов для обеих поверхностей.

`GET /`, `GET /v1/` и `GET /v2/` возвращают список маршрутов v1, начиная с <Src repo="node" path="api/src/handlers.rs" line={606} />. `GET /v1/` требует учётные данные,
как и остальные маршруты этого префикса.

### Маршруты {/* #routes */}

Глаголы указаны так, как их сообщает индекс маршрутов узла. В правом столбце — метод JSON-RPC,
возвращающий те же данные, и его поверхность.

<details>
<summary>Все маршруты v1 и их эквиваленты в JSON-RPC</summary>

Маршрутизатор регистрирует 18 шаблонов, шесть из них — с подстановочными знаками: `blocks/*`, `headers/*`,
`chain/outputs/*`, `chain/kernels/*`, `txhashset/*` и `peers/**`.

| Маршрут | Метод | JSON-RPC эквивалент |
| --- | --- | --- |
| `/v1/` | GET | нет, это индекс маршрутов |
| `/v1/status` | GET | `get_status`, Owner |
| `/v1/chain` | GET | `get_tip`, Foreign |
| `/v1/chain/validate` | GET | `validate_chain`, Owner |
| `/v1/chain/compact` | POST | `compact_chain`, Owner |
| `/v1/blocks/<hash\|height>` | GET | `get_block`, Foreign |
| `/v1/headers/<hash\|height\|commit>` | GET | `get_header`, Foreign |
| `/v1/chain/kernels/<excess>?min_height=&max_height=` | GET | `get_kernel`, foreign |
| `/v1/chain/outputs/byids?id=` | GET | `get_outputs`, foreign |
| `/v1/chain/outputs/byheight?start_height=&end_height=` | GET | `get_outputs`, foreign |
| `/v1/txhashset/roots` | GET | нет |
| `/v1/txhashset/lastoutputs?n=` | GET | нет |
| `/v1/txhashset/lastrangeproofs` | GET | нет |
| `/v1/txhashset/lastkernels` | GET | `get_last_n_kernels`, foreign |
| `/v1/txhashset/outputs?start_index=&max=` | GET | `get_unspent_outputs`, foreign |
| `/v1/txhashset/merkleproof?n=` | GET | `include_merkle_proof` на `get_outputs`, foreign |
| `/v1/pool` | GET | `get_pool_size` и `get_stempool_size`, foreign |
| `/v1/pool/push_tx` | POST | `push_transaction`, foreign |
| `/v1/peers/all` | GET | `get_peers`, owner |
| `/v1/peers/connected` | GET | `get_connected_peers`, owner |
| `/v1/peers/<addr>` | GET | `get_peers` с `peer_addr`, owner |
| `/v1/peers/<addr>/ban` | POST | `ban_peer`, owner |
| `/v1/peers/<addr>/unban` | POST | `unban_peer`, owner |
| `/v1/peers/onion_addresses` | GET | `get_onion_addresses`, owner |
| `/v1/version` | GET | `get_version`, foreign. Единственный маршрут `/v1`, не требующий учётных данных |
| `/v1/mining/block_template` | GET | `get_block_template`, foreign |

</details>

Вызов `/v1`, требующий учётные данные узла. Без `-u` или на узле без `api_secret_path` возвращается 401:

```bash
curl -s -u epic:$(cat ~/.epic/main/.api_secret) http://127.0.0.1:3413/v1/status
```

    "prev_block_to_last": "6ceed7ff0ff7da1d44b01dc03189edeb1323bfa6d3625768520dd1a0498a0735",
    "total_difficulty": {"cuckaroo": 1440, "cuckatoo": 1440, "randomx": 1440, "progpow": 1440}

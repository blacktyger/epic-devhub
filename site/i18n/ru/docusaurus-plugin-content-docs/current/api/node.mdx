# Node API

Узел обслуживает JSON-RPC 2.0 на одном слушателе, привязанном к `127.0.0.1` порту <Ver k="ports.nodeApi" /> по умолчанию,
разделённом на два интерфейса.

| Поверхность | Путь | Обслуживает |
| --- | --- | --- |
| Owner | `/v2/owner` | Администрирование узла, восемь методов |
| Foreign | `/v2/foreign` | Чтение цепочки, отправка транзакций, шаблоны блоков, семнадцать методов |

Учётные данные и то, какой из этих интерфейсов их требует, описаны в разделе [аутентификация и
TLS](/api/authentication).

Тот же слушатель также предоставляет REST-интерфейс по адресу `/v1`. См. [REST-интерфейс v1](#the-v1-rest-surface).

## Какой JSON-RPC метод где находится {/* #which-json-rpc-method-lives-where */}

`/v2/owner` — только администрирование узла:

`get_status`, `validate_chain`, `compact_chain`, `get_peers`, `get_connected_peers`, `ban_peer`, `unban_peer`, `get_onion_addresses`.

`/v2/foreign` — всё остальное, включая все операции чтения цепочки и отправку транзакций:

`get_header`, `get_block`, `get_blocks`, `get_tip`, `get_version`, `get_kernel`, `get_last_n_kernels`, `get_outputs`, `get_unspent_outputs`, `get_pmmr_indices`, `get_pool_size`, `get_stempool_size`, `get_unconfirmed_transactions`, `push_transaction`, `get_block_template`, `finalize_block_template`,
`submit_block`.

Таким образом, чтение блока — это вызов к foreign-интерфейсу, и на стандартной установке учётные
данные не требуются:

```bash
curl -s -d '{"jsonrpc":"2.0","method":"get_tip","params":[],"id":1}' \
  http://127.0.0.1:3413/v2/foreign
```

Проверка состояния синхронизации — вызов owner-интерфейса, требующий [учётных данных узла](/api/authentication#the-node-credential).

## Форматы ответов {/* #response-shapes */}

`total_difficulty` — объект с ключами по алгоритму доказательства работы (proof of work), а не целое число:

```json
{
  "total_difficulty": {
    "cuckaroo": 0,
    "cuckatoo": 1234,
    "randomx": 5678,
    "progpow": 9012
  }
}
```

Заголовки блоков описывают своё доказательство двумя полями: `proof` — строка с именем алгоритма, и
`solution` — размеченное объединение, форма которого определяется этим алгоритмом.

`Status` включает `supply` и `max_supply` в целых EPIC, а не в freemen, и `blocks_to_next_halving` как количество блоков. Шаги эмиссии —
не все халвинги; см. [эмиссия](/mining/emission).

Ядра (kernels) представлены в двух формах в зависимости от метода. `get_block` возвращает плоскую форму,
тогда как `get_kernel` и `get_last_n_kernels` возвращают исходный тип с внешне размеченным полем `features`. Необходимо
обрабатывать обе формы.

## Майнинг через HTTP {/* #mining-over-http */}

Foreign-интерфейс предлагает трёхшаговый процесс отправки блока как альтернативу Stratum: `get_block_template`,
`finalize_block_template`, `submit_block`. Используется JSON-RPC поверх HTTP. См. [Stratum](/mining/stratum).

## REST-поверхность v1 {/* #the-v1-rest-surface */}

Узел обслуживает REST по адресу `/v1` и JSON-RPC по адресу `/v2` из одного процесса на одном порту.
Числа обозначают два стиля интерфейса, а не два поколения: `/v1` зарегистрирован по адресу <Src repo="node" path="api/src/handlers.rs" line={536} />, `/v2`
— по адресам <Src repo="node" path="api/src/handlers.rs" line={135} /> и <Src repo="node" path="api/src/handlers.rs" line={155} />.

Разница заключается в том, где указывается имя операции.

|  | `/v1` | `/v2` |
| --- | --- | --- |
| Стиль | REST | JSON-RPC 2.0 |
| Операция задаётся | путём URL | полем `method` в теле запроса |
| HTTP-глаголом | `GET`, `POST` для мутаций | `POST` |
| URL-адреса | по одному на операцию | `/v2/foreign`, `/v2/owner`, `/v2/tor` |
| Результат | полезная нагрузка | полезная нагрузка внутри `result.Ok` |
| Учётные данные | Basic auth для префикса `/v1` | для каждого интерфейса |

Оба интерфейса возвращают одинаковые данные. `GET /v1/status` и `get_status` на `/v2/owner` возвращают идентичные тела ответов,
поэтому [страницы JSON-RPC](#full-method-reference) документируют форматы ответов для обоих.

`GET /`, `GET /v1/` и `GET /v2/` возвращают список маршрутов v1, начиная с <Src repo="node" path="api/src/handlers.rs" line={446} />.

### Маршруты {/* #routes */}

Глаголы соответствуют тому, как их сообщает индекс маршрутов узла. Правый столбец — метод JSON-RPC,

| `/v1/headers/<hash\|height\|commit>` | GET | `get_header`, foreign |
| `/v1/chain/kernels/<excess>?min_height=&max_height=` | GET | `get_kernel`, foreign |

| `/v1/pool/push_tx` | POST | `push_transaction`, foreign |

| `/v1/peers/connected` | GET | `get_connected_peers`, owner |

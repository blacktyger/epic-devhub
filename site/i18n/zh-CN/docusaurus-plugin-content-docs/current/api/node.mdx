# Node API

节点在单个监听器上提供JSON-RPC 2.0服务，默认绑定到`127.0.0.1`端口<Ver k="ports.nodeApi" />，分为两个接口层。

| 接口 | 路径 | 服务 |
| --- | --- | --- |
| Owner | `/v2/owner` | 节点管理，<Ver k="apiMethods.nodeOwner" />个方法 |
| Foreign | `/v2/foreign` | 链读取、交易提交、区块模板，<Ver k="foreignApiMethods" />个方法 |

凭据及哪个接口层需要凭据，统一在[身份验证与TLS](/api/authentication)中说明。

同一监听器还在`/v1`下提供REST接口层。参见[v1 REST接口层](#the-v1-rest-surface)。

## JSON-RPC方法分布 {/* #which-json-rpc-method-lives-where */}

`/v2/owner`仅用于节点管理：

`get_status`, `validate_chain`, `compact_chain`, `get_peers`, `get_connected_peers`, `ban_peer`, `unban_peer`, `get_onion_addresses`.

`/v2/foreign`用于其他所有操作，包括所有链读取和交易提交：

`ready_for_txs`, `get_header`, `get_block`, `get_blocks`, `get_tip`, `get_version`, `get_kernel`, `get_last_n_kernels`, `get_outputs`, `get_unspent_outputs`, `get_pmmr_indices`, `get_pool_size`, `get_stempool_size`, `get_unconfirmed_transactions`, `push_transaction`, `get_block_template`, `finalize_block_template`, `submit_block`.

因此，读取区块是Foreign API调用，在默认安装下无需凭据：

```bash
curl -s -d '{"jsonrpc":"2.0","method":"get_tip","params":[],"id":1}' \
  http://127.0.0.1:3413/v2/foreign
```

检查节点是否已同步也是Foreign API的调用。`ready_for_txs`仅在同步状态为`no_sync`时返回`{"ready_for_txs": true}`，否则返回`false`，且无需凭据：

```bash
curl -s -d '{"jsonrpc":"2.0","method":"ready_for_txs","params":[],"id":1}' \
  http://127.0.0.1:3413/v2/foreign
```

包含区块高度、对等节点和命名同步状态的完整状态，通过Owner API上的`get_status`获取。通常需要[节点凭据](/api/authentication#the-node-credential)，但第一次普通`get_status`调用无需凭据即可响应。

## 响应结构 {/* #response-shapes */}

`total_difficulty`是以工作量证明（proof-of-work）算法为键的对象，而非整数：

```json
{
  "total_difficulty": {
    "cuckaroo": 0,
    "cuckatoo": 1234,
    "randomx": 5678,
    "progpow": 9012
  }
}
```

区块头用两个字段描述其证明：`proof`，一个命名算法的字符串；`solution`，一个外部标记联合体，其结构随算法而变。

`Status`中的`supply`和`max_supply`以整数EPIC而非freemen为单位，`blocks_to_next_halving`以区块数计。奖励步骤并非全部为减半；参见[发行](/mining/emission)。

内核（kernel）在不同方法中以两种形式出现。`get_block`返回扁平化形式，而`get_kernel`和`get_last_n_kernels`返回带有外部标记`features`字段的原始类型。两种形式均需处理。

## HTTP挖矿 {/* #mining-over-http */}

Foreign API提供三步区块提交流程，作为Stratum的替代方案：`get_block_template`、`finalize_block_template`、`submit_block`。通过HTTP上的JSON-RPC调用。参见[Stratum](/mining/stratum)。

## v1 REST接口 {/* #the-v1-rest-surface */}

节点在同一进程的同一端口上，分别在`/v1`下提供REST服务，在`/v2`下提供JSON-RPC服务。编号代表两种接口风格，而非两代版本：`/v1`注册在<Src repo="node" path="api/src/handlers.rs" line={692} />，`/v2`注册在<Src repo="node" path="api/src/handlers.rs" line={132} />和<Src repo="node" path="api/src/handlers.rs" line={152} />。

区别在于操作名称的位置。

|  | `/v1` | `/v2` |
| --- | --- | --- |
| 风格 | REST | JSON-RPC 2.0 |
| 操作由以下内容命名 | URL路径 | 请求体中的`method`字段 |
| HTTP动词 | `GET`，`POST`用于修改 | `POST` |
| URL | 每个操作一个 | `/v2/foreign`, `/v2/owner`, `/v2/tor` |
| 结果 | 载荷本身 | `result.Ok`内的载荷 |
| 凭据 | `/v1`前缀下的Basic auth，`GET /v1/version`除外 | 每个接口各自独立 |

两个接口层返回相同的载荷。`/v2/owner`上的`GET /v1/status`和`get_status`产生相同的响应体，因此[JSON-RPC页面](#full-method-reference)为两者记录响应结构。

`GET /`、`GET /v1/`和`GET /v2/`从<Src repo="node" path="api/src/handlers.rs" line={606} />返回v1路由列表。`GET /v1/`与该前缀下的其他路由一样需要凭据。

### 路由 {/* #routes */}

HTTP动词以节点路由索引所报告的为准。右列为返回相同内容的JSON-RPC方法及其所属接口层。

<details>
<summary>所有v1路由及其对应的JSON-RPC方法</summary>

路由器注册了<Ver k="v1Routes" />个模式，其中<Ver k="v1Wildcards" />个为通配符：`blocks/*`、`headers/*`、`chain/outputs/*`、`chain/kernels/*`、`txhashset/*`和`peers/**`。

| 路由 | 动词 | JSON-RPC等效方法 |
| --- | --- | --- |
| `/v1/` | GET | 无，此为路由索引 |
| `/v1/status` | GET | `get_status`，owner |
| `/v1/chain` | GET | `get_tip`，foreign |
| `/v1/chain/validate` | GET | `validate_chain`，owner |
| `/v1/chain/compact` | POST | `compact_chain`，owner |
| `/v1/blocks/<hash\|height>` | GET | `get_block`，foreign |
| `/v1/headers/<hash\|height\|commit>` | GET | `get_header`，foreign |
| `/v1/chain/kernels/<excess>?min_height=&max_height=` | GET | `get_kernel`，foreign |
| `/v1/chain/outputs/byids?id=` | GET | `get_outputs`，foreign |
| `/v1/chain/outputs/byheight?start_height=&end_height=` | GET | `get_outputs`，foreign |
| `/v1/txhashset/roots` | GET | 无 |
| `/v1/txhashset/lastoutputs?n=` | GET | 无 |
| `/v1/txhashset/lastrangeproofs` | GET | 无 |
| `/v1/txhashset/lastkernels` | GET | `get_last_n_kernels`，foreign |
| `/v1/txhashset/outputs?start_index=&max=` | GET | `get_unspent_outputs`，foreign |
| `/v1/txhashset/merkleproof?n=` | GET | `include_merkle_proof`在`get_outputs`上，foreign |
| `/v1/pool` | GET | `get_pool_size`和`get_stempool_size`，foreign |
| `/v1/pool/push_tx` | POST | `push_transaction`，foreign |
| `/v1/peers/all` | GET | `get_peers`，owner |
| `/v1/peers/connected` | GET | `get_connected_peers`，owner |
| `/v1/peers/<addr>` | GET | `get_peers`附带`peer_addr`，owner |
| `/v1/peers/<addr>/ban` | POST | `ban_peer`，owner |
| `/v1/peers/<addr>/unban` | POST | `unban_peer`，owner |
| `/v1/peers/onion_addresses` | GET | `get_onion_addresses`，owner |
| `/v1/version` | GET | `get_version`，foreign。唯一无需凭据的`/v1`路由 |
| `/v1/mining/block_template` | GET | `get_block_template`，foreign |

</details>

`/v1`调用需要节点凭据。若缺少`-u`，或节点未配置`api_secret_path`，则返回401：

```bash
curl -s -u epic:$(cat ~/.epic/main/.api_secret) http://127.0.0.1:3413/v1/status
```

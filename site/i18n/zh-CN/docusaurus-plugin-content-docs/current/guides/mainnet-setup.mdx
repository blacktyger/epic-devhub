# 为mainnet设置节点和钱包

Mainnet使用真实价值。本文所有内容均假设你已完成[运行本地网络](/guides/local-network)和[首次转账](/guides/first-transfer)中的操作，因为两者的操作机制完全相同，但后果截然不同。

两个进程。一个节点负责验证和中继链，一个钱包负责持有密钥并向节点查询世界状态。你需要一个节点，不需要挖矿。

## 1. 启动节点 {/* #1-start-the-node */}

mainnet是默认网络，因此无需任何参数：

```bash
epic
```

节点在首次运行时写入`epic-server.toml`，此后从该文件读取配置。编辑该文件是更改行为的常规方式，因为大多数设置仅以配置键的形式存在，而非命令行参数。每个键的修改都需要重启节点。

确认节点已启动。owner接口需要身份验证，机密文件会自动为你创建：

<Tabs groupId="os">
<TabItem value="linux" label="Linux 和 macOS">

```bash
curl -s -u epic:$(cat ~/.epic/main/.api_secret) -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","method":"get_status","params":[],"id":1}' \
  http://127.0.0.1:3413/v2/owner
```

</TabItem>
<TabItem value="win" label="Windows">

```powershell
$secret = (Get-Content "$HOME\.epic\main\.api_secret" -First 1).Trim()
$body = '{"jsonrpc":"2.0","method":"get_status","params":[],"id":1}'
Invoke-RestMethod -Uri 'http://127.0.0.1:3413/v2/owner' -Method Post `
  -ContentType 'application/json' -Body $body `
  -Authentication Basic -Credential (
    [PSCredential]::new('epic', (ConvertTo-SecureString $secret -AsPlainText -Force))
  ) -AllowUnencryptedAuthentication
```

</TabItem>
</Tabs>

首次同步会下载并验证整条链。预计耗时较长，并会占用实际磁盘空间。

### 端口 {/* #ports */}

| 端口 | 用途 | 默认绑定 |
| --- | --- | --- |
| <Ver k="ports.nodeApi" /> | HTTP API | `127.0.0.1` |
| <Ver k="ports.nodeP2p" /> | P2P | 所有接口 |
| <Ver k="ports.stratum" /> | Stratum挖矿服务器 | `127.0.0.1`，默认关闭 |

只有P2P端口需要对外部可达。将API保持在回环地址上，并在更改之前阅读[身份验证与TLS](/api/authentication)。所有端口和网络偏移量均在[CLI参考](/reference/cli#ports)中列出。

### 同步验证设置 {/* #sync-validation-settings */}

`skip_pow_validation`默认为`true`，`disable_checkpoints`默认为`false`。在已检查点范围内跳过工作量证明（proof of work）是一种同步速度优化，而非降低安全性的默认设置：跳过的范围终止于一个硬编码检查点，该检查点的哈希值必须匹配，且范围内的每个区块头都链接回该检查点。只有位于<Ver k="checkpointCount" />检查点高度处的区块头通过哈希进行比较，其间的区块头不做比较。

| 区块所在位置 | 在mainnet上执行验证 |
| --- | --- |
| 在检查点范围内，最高至区块高度<Ver k="lastCheckpointHeight" /> | 检查点高度处的区块头与硬编码哈希进行比对，不匹配则中止同步。`skip_pow_validation`为`true`时跳过工作量证明验证 |
| 在最后一个检查点之上 | **始终执行完整工作量证明，无论这些设置如何** |

只有当批次中的每个区块头都通过检查点验证时，该批次才被视为已检查点。

节点中编译了<Ver k="checkpointCount" />个检查点，位于<Src repo="node" path="chain/src/types.rs" line={432} />。代码为<Fn repo="node" path="chain/src/chain.rs" line={1545} name="check_header_against_checkpoints" />，跳过决策为<Fn repo="node" path="servers/src/common/adapters.rs" line={51} name="should_skip_pow" />，节点在mainnet上启动时会记录日志，说明适用哪种策略。

`disable_checkpoints`在mainnet上被忽略。在测试网络上，当`skip_pow_validation`也为`true`时，它将跳过范围延伸至最后一个检查点之后，适用于距链顶端超过<Ver k="powVerificationThreshold" />个区块的区块（<Fn repo="node" path="servers/src/common/adapters.rs" line={45} kind="const" name="POW_VERIFICATION_THRESHOLD" />）。

将`skip_pow_validation = false`设置为自行验证所有历史工作量证明。这会导致初始同步时间大幅增加。

### 节点存储的内容 {/* #what-the-node-stores */}

`chain_data`、配置文件、日志文件和API机密。`chain_data`是占用空间较大的项目，且可以丢弃，因此删除它只需重新同步，不会有其他损失。节点不持有任何密钥，因此其数据目录中的内容无需备份。

## 2. 创建钱包 {/* #2-create-the-wallet */}

```bash
epic-wallet init
```

系统会要求你设置密码，并显示一个恢复助记词。

:::danger[Write the recovery phrase down before continuing]

助记词是唯一能够重建你的资金的凭据。它仅在此处显示一次，之后只能通过`epic-wallet recover`查看，而该操作需要密码。

:::

| 命令 | 效果 |
| --- | --- |
| `epic-wallet init` | 在默认位置创建钱包，`~/.epic/main` |
| `epic-wallet init -w` | 在当前目录创建。该参数不接受值 |
| `epic-wallet init -r` | 从已有恢复助记词恢复 |

如果种子文件已存在，`init -r`将拒绝运行，因此若要恢复到一个已有钱包的目录，需先将该钱包移至其他位置。参见[备份与恢复](/guides/backup-and-restore)。

### 关闭Tor监听器 {/* #turn-off-the-tor-listener */}

钱包将`use_tor_listener`默认设置为`true`，并期望发布版本归档中未附带的Tor二进制文件，因此`epic-wallet listen`会启动一个后台线程并失败。有两种方式可以关闭它，其中一种是按命令生效：

```toml title="epic-wallet.toml"
[tor]
use_tor_listener = false
```

```bash
epic-wallet listen -n
```

`-n`仅在`listen`上声明（<Src repo="wallet" path="src/cmd/wallet_args.rs" line={123} />），因此必须在每个`listen`上重复指定。配置键适用于该钱包目录中的所有命令，是推荐使用的设置。两者均不影响节点对Tor的使用。

### 钱包存储的内容 {/* #what-the-wallet-stores */}

[备份与恢复](/guides/backup-and-restore#what-to-back-up)列出了钱包目录中的每个文件、其内容以及是否需要备份。恢复助记词可重建你的资金，但无法恢复历史记录。交易记录、账户标签和支付证明记录仅存储在数据库中，链上的任何内容都无法重建它们。

### 钱包开放的端口 {/* #ports-the-wallet-opens */}

`epic-wallet listen`在<Ver k="ports.walletForeign" />上开启Foreign API，`epic-wallet owner_api`在<Ver k="ports.walletOwner" />上开启Owner API。Foreign端口由网络决定；Owner端口在所有网络上均为<Ver k="ports.walletOwner" />，因此同一台机器上的第二个钱包无论运行哪条链，都会在该端口发生冲突。覆盖`owner_api_listen_port`。完整列表见[CLI参考](/reference/cli#ports)。

## 3. 将钱包指向节点 {/* #3-point-the-wallet-at-the-node */}

钱包默认连接到回环地址上端口<Ver k="ports.nodeApi" />的节点。无需配置。

钱包的调用发往节点中无需凭据的接口，因此移动任一目录不会导致连接中断。`node_api_secret_path`仅用于Tor洋葱地址查找；参见[钱包向节点提交的凭据](/api/authentication#the-credential-the-wallet-presents-to-the-node)。如需连接其他节点，在`epic-wallet.toml`中设置`check_node_api_http_addr`。

```bash
epic-wallet info
```

余额为零且无报错，表示钱包已成功连接节点且节点已响应。401表示节点设置了`foreign_api_secret_path`，而epic-wallet <Ver k="wallet" />无法与之配合使用。根据代码，版本早于<Ver k="node" />且设置了API机密的节点同样会返回401；该组合尚未经过测试。

将钱包指向公共节点可以正常使用。但该节点会看到钱包查询的输出（output），且钱包不会验证所获得的链状态。
